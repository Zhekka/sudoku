# Судоку — распознавание и решение фото

Android-приложение: фотографируете (или выбираете из галереи) судоку — приложение
находит сетку, кадрирует по перспективе, распознаёт цифры нейросетью, показывает
предпросмотр для правки и решает задачу. Готовые решения сохраняются в истории.

Три способа ввести задачу:

* **Сделать фото** — съёмка камерой, затем кадрирование и распознавание;
* **Выбрать изображение** — картинка из галереи, дальше тот же путь;
* **Ввести вручную** — пустая сетка 9×9, цифры вводятся панелью 1–9, без камеры.

Во всех трёх случаях дальше идёт общий экран предпросмотра с правкой чисел →
решение → история (в истории источник помечен как «фото», «файл» или «ручной ввод»).

Тема переключается кнопкой с лампой/лунаци на главном экране: светлая или тёмная,
выбор запоминается между запусками, при первом запуске берётся системная тема.

## Где что

* **нейросеть** — только распознавание цифр (`ml/DigitRecognizer.kt`), локально через TFLite;
* **кадрирование** — классическая CV-цепочка без нейросети (`image/GridExtractor.kt`):
  граница ищется по схеме из `проект.ipynb` — внешний контур → `approxPolyDP(0.04·периметра)`
  → выпуклый четырёхугольник с макс. периметром → перспективное преобразование (без OpenCV);
* **решение** — алгоритм backtracking + MRV (`core/SudokuSolver.kt`), без нейросети.

## Как это работает

```
Фото (камера / галерея)
   └─ GridExtractor.prepare      уменьшение до 1400 px
   └─ GaussianBlur 7×7 (σ=1.4) + порог Оцу
   └─ связные компоненты         разметка компонент «чернил» (4-связность)
   └─ внешний контур (Мур)       замыкающий обход компоненты, как findContours(RETR_EXTERNAL)
   └─ approxPolyDP(0.04·P)       упрощение контура → 4 вершины, выпуклость, макс. периметр
   └─ запасной путь              если контур не четырёхугольник: углы по диагоналям + PCA-прямые
   └─ экран «Кадрирование»      углы можно подвинуть пальцем (ручная правка)
   └─ гомографика → 306×306      перспективное преобразование (34 px × 9)
   └─ 81 клетка → центр 28×28   ровно как в ноутбуке (block_size 34, shift 3)
   └─ эвристика пустоты         ≥ 11 % «чернил» в области смещений 6/8/10
   └─ TFLite-модель             [1,28,28,1] float32 → [1,10] softmax
   └─ предпросмотр              правка цифр, подсветка низкой уверенности и конфликтов
   └─ решатель (MRV backtracking) → решение → история
```

Пороги распознавания: `conf ≥ 0.5` — цифра считана (как в ноутбуке), `conf < 0.85` —
клетка помечается как «проверьте». Класс `0` и `conf < 0.5` трактуются как пустая
клетка. Если модель видит «чернил», но не смогла прочитать цифру, клетка тоже
помечается для ручной правки.

## Структура

```
app/src/main/java/com/sudoku/recognizer/
├── MainActivity.kt          один Activity, переключение экранов состоянием
├── AppViewModel.kt          пайплайн, состояние, история
├── image/GridExtractor.kt   детекция сетки, кадрирование, нарезка клеток (без OpenCV)
├── ml/DigitRecognizer.kt    обёртка TFLite
├── core/SudokuSolver.kt     ветвление с эвристикой MRV + проверка конфликтов
├── core/History.kt          история решений (JSON в filesDir)
└── ui/                      Home, Camera, Crop, Preview/Solution, History, сетка
app/src/main/assets/sudoku_model.tflite
tools/convert_to_tflite.py   .keras → .tflite + сверка предсказаний
tools/verify_pipeline.py     сквозная проверка пайплайна на синтетическом судоку
```

## Сборка

Нужен Android Studio (JDK 17) — проект собирается как обычный Gradle-проект:

```bash
./gradlew assembleDebug     # APK: app/build/outputs/apk/debug/app-debug.apk
./gradlew test              # юнит-тесты решателя и сериализации
```

Требования: `compileSdk 35`, `minSdk 24`, Kotlin 2.0.21, AGP 8.7.3, Compose BOM 2024.09.03,
`org.tensorflow:tensorflow-lite:2.16.1`, CameraX 1.3.4.

## Модель

Исходник — `sudoku_model_improved.keras` из ноутбука (CNN 32/64/128 + BatchNorm,
обучена на MNIST + 50 000 синтетических печатных цифр). Конвертация:

```bash
python tools/convert_to_tflite.py   # → app/src/main/assets/sudoku_model.tflite
```

Скрипт дополнительно сверяет TFLite с Keras: расхождение вероятностей 0.000000,
совпадение предсказаний на 500 примерах MNIST — 1.0000, точность 99.6 %.

## Проверено

* `./gradlew assembleDebug` — сборка успешна, APK 33 МБ;
* `./gradlew test` — 6/6 тестов решателя (решение классической задачи, конфликты,
  отказ при противоречии, сериализация сетки);
* `tools/verify_pipeline.py` — на синтетическом фото: углы найдены с точностью
  3.0 px (внешний контур + approxPolyDP), эвристика пустоты дала ровно 30
  заполненных клеток, 81/81 цифр распознано.

Не проверялось здесь: запуск на реальном устройстве (камера, жесты кадрирования,
сохранение истории) — эти сценарии нужно прогнать вручную.

## Известные ограничения

* Граница ищется по внешнему контуру тёмной области: если у судоку нет внешней
  рамки, контур не сводится к четырём вершинам и включается запасной путь — углы
  определяются по крайним линиям, их стоит подвинуть на экране кадрирования.
* Текст интерфейса захардкожен на русском (нет `strings.xml` для локализаций).
* Камера только задняя, без вспышки и зума.
